# Гейт проверяет ИЗМЕНЕНИЕ, а не весь репозиторий

Происхождение: projectx-app, 2026-07-27. Владелец: «который гоняет весь репозиторий,
чтобы такого не повторялось, из-за этого виснет весь компьютер и Claude Code, реши эту
проблему на системном уровне».

## Что было

`.husky/pre-push` на каждый пуш запускал полный набор:

- `tsc --noEmit` по всему проекту,
- **все** тесты — 2197 тестовых файлов,
- `next build` — причём хук перед этим делал `rm -rf .next`, поэтому сборка всегда была
  холодной (1–3 минуты) даже когда изменения её вообще не касались,
- бюджет бандла и покрытие.

Итог: 7+ минут на пуш, пик памяти уводил машину в своп, Claude Code вставал колом.
Пуш просто не доходил до конца — его убивали по таймауту. А гейт, который невозможно
дождаться, начинают обходить через `--no-verify`, то есть он перестаёт защищать вообще.

## Правило

**Стоимость гейта должна быть пропорциональна размеру изменения.** Локальный хук
проверяет то, что затронуто; полный прогон живёт на главных ветках и в CI.

Конкретная раскладка, проверенная на практике:

| Проверка | Локально на рабочей ветке | Полностью |
|---|---|---|
| Типы | всегда (инкрементальная, секунды) | всегда |
| Тесты | только связанные с изменёнными файлами (`vitest related`) | на dev/main, при правке конфигов тестов или зависимостей |
| Сборка | только если изменены маршруты (`app/`), `next.config`, `package.json`, `tsconfig` | там же |
| Бюджет бандла | только если сборка реально запускалась | там же |

Замер на projectx-app: выборочный прогон затронул **10 тестовых файлов из 2197** и занял
**39 секунд** вместо полного прогона.

## Три обязательных детали

1. **Не удалять кеш сборки «на всякий случай».** `rm -rf .next` в хуке превращает каждую
   сборку в холодную. Чистить кеш должен тот шаг, которому это нужно, и только перед
   собой.
2. **Таймаут на каждый шаг.** Зависший шаг обязан быть убит, а не держать пуш вечно.
   Без таймаута «медленно» превращается в «навсегда».
3. **Пропущенное называть вслух.** Молчаливый пропуск читается как «всё проверено».
   Гейт печатает строку вида «пропущено: сборка (маршруты и конфиги не менялись)».

## Чего это НЕ означает

Это не ослабление гейта. То, что изменение может сломать, по-прежнему проверяется
и по-прежнему блокирует пуш. Убрано только то, чего изменение не касается. Порог
поднимается обратно автоматически: ветка dev/main, правка конфигов сборки или
инфраструктуры тестов, больше 150 изменённых файлов — полный прогон.

## Реализация-образец

`scripts/verify-gate.mjs` в projectx-app: флаг `--scope=auto|full`, определение базы через
`git merge-base HEAD origin/dev`, список изменений через `git diff --name-only base...HEAD`,
`vitest related` для тестов, регулярка чувствительных к сборке путей, таймаут и потолок
памяти на каждый шаг.

## Смежные уроки

- `~/.claude/rules/` — замок `--wait` в common-launcher (две сессии не гоняют два гейта
  одновременно; замер 2026-07-24: 9 параллельных tsc, 14.8 ГБ свопа).
- Класс в мета-леджере: `gate-cost-not-proportional-to-change`.

## Сторож тяжёлой задачи обязан иметь обход для внутренних вызовов

Происхождение: projectx-app 2026-07-28. Сторож `scripts/tsc-guard.mjs` подменяет
`node_modules/.bin/tsc` и пропускает ОДИН тяжёлый прогон за раз — он появился
после того, как параллельные проверки дважды за день уронили Mac. Правильная
защита. Но она молча сломала девять тестов: они запускали `npx tsc --noEmit`
внутри себя, попадали в ту же очередь, где уже стоял сам прогон vitest, и
висели до таймаута. Внешне это выглядело как «типы сломаны» — на деле типы были
чистые, а прогон занимал 730 секунд ожидания вместо 5 секунд работы.

Замер, который это вскрыл:

```
npx tsc --noEmit --skipLibCheck                        → 730 с (ожидание очереди)
node node_modules/typescript/bin/tsc --noEmit ...      → 4.9 с
```

Правило: если сторож сериализует инструмент, у вызывающих ИЗНУТРИ уже
запущенной тяжёлой задачи должен быть прямой путь к бинарю мимо очереди —
иначе получается самоблокировка. Прямой вызов ставится с потолком памяти, и
на весь запуск он должен быть ОДИН (кешируйте результат), иначе смысл сторожа
теряется.

Дополнительно: двадцать шесть тестов, каждый из которых полностью
типизирует проект, — это та же болезнь, что «гейт гоняет весь репозиторий».
Один общий кешированный прогон на запуск покрывает ровно тот же смысл.
Образец: `projectx-app/tests/_helpers/tscOnce.ts`.

Класс в мета-леджере: `guard-deadlocks-its-own-callers`.
