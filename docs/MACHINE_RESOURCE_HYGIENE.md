# Гигиена ресурсов машины — почему Claude Code «жрёт оперативу»

Происхождение: projectx 2026-07-24. Владелец: «клауд код опять сильно ест, комп зависает,
разберись на системном и архитектурном уровне». Второй заход за трое суток — 2026-07-21
чинили осиротевшие `uv`-обёртки, 2026-07-24 (утро) наложение фоновых гейтов. Симптом
возвращался, потому что каждый раз лечили ОДИН источник, а механика общая.

## Сначала — отчёт JetsamEvent, а не догадки

Когда машина уже легла и её перезагрузили, живые процессы улик не содержат. macOS пишет
`/Library/Logs/DiagnosticReports/JetsamEvent-*.ips` — снимок ВСЕХ процессов с их резидентной
памятью на момент нехватки. Это точный список виновников, читать его первым:

```bash
ls -t /Library/Logs/DiagnosticReports/JetsamEvent*.ips | head -3
python3 -c "
import json,sys
b=json.loads(open(sys.argv[1]).read().split(chr(10),1)[1])
r=sorted((p.get('rpages',0)*16384/1048576, p.get('name')) for p in b['processes'])[::-1]
print(f'всего {sum(x[0] for x in r):.0f} МБ'); [print(f'{mb:8.0f} MB  {n}') for mb,n in r[:15]]
" /Library/Logs/DiagnosticReports/JetsamEvent-<дата>.ips
```

Поле памяти называется `rpages` (страницы по 16 КБ), не `pageCount`. Сверять pid из отчёта
с более ранним снимком `ps` — так безымянный «node» превращается в конкретную команду.

**Цена пропуска этого шага (2026-07-24):** вылечил MCP, отчитался, через два часа машина легла
снова — 25 ГБ оказались в девяти `tsc`. Проверять надо «что именно съело память», а не «стало
ли меньше того, что я чинил».

## Проверка типов дороже, чем кажется

На большом репозитории один `tsc --noEmit` честно берёт ~3 ГБ (замер: пик 3107 МБ, с потолком
2 ГБ падает по heap). Это не утечка — это цена. Поэтому:

- Потолок кучи не лечит, он только превращает падение машины в падение прогона.
- **Лечит замок: один `tsc` на машину за раз.** Одну такую проверку 18 ГБ держат, девять — нет.
- Ограничитель ставится на сам бинарь (`node_modules/.bin/tsc` → обёртка), а не на свои скрипты:
  `npx tsc --noEmit` живёт в критериях приёмки десятков спек, и его запускает кто угодно когда угодно.
- `npm install` возвращает оригинальный симлинк — восстановление обёртки вешается на `postinstall`,
  иначе защита исчезает молча.
- Тестовый прогон ограничивается по числу воркеров (по умолчанию берётся ядра-1). В Vitest 4
  работает только `maxWorkers`; `poolOptions`/`maxForks`/`maxThreads` из типов убраны.

## Механика: множитель, а не утечка

Это почти никогда не утечка одного процесса. Это **умножение**:

```
(число открытых окон Claude) × (число MCP на окно) × (2, если MCP объявлен через npx)
```

Каждое окно поднимает ПОЛНЫЙ набор MCP заново. Замер на 18 ГБ Mac: 10 сессий × 11 глобальных
серверов = 106 процессов, 5.4 ГБ. Плюс 40 обёрток `npm exec` по 51-78 МБ = ещё 2 ГБ впустую.

**Диагностическая ловушка:** сортировка `ps` по RSS обманывает. Машина под свопом показывает
у всех процессов маленький RSS — память сжата компрессором. Виновника ищут суммой по группам.

```bash
sysctl vm.swapusage; vm_stat | tail -10        # компрессор + своп = реальная картина
pgrep -f 'claude-code/.*MacOS/claude' | wc -l  # число окон — множитель для всего остального
ps -Axo rss,command | awk '/^ *[0-9]+ npm exec/{s+=$1;c++} END{print c" обёрток = "s/1024" МБ"}'
ps -Axo pid,ppid,etime,command | awk '$2==1'   # осиротевшие: родитель launchd => сеанс мёртв
```

## Три правила

### 1. MCP объявляется прямым путём, никогда через `npx`

`npx -y пакет@latest` поднимает ДВА процесса: обёртку npm, которая ничего не делает,
и сам сервер. Обёртка стоит 51-78 МБ и умножается на число окон. Плюс `@latest` — сетевая
проверка при каждом старте.

Правильно: установить пакеты один раз в общую папку и звать бинарь напрямую.

```bash
mkdir -p ~/.claude/mcp-bin && cd ~/.claude/mcp-bin
npm install @playwright/mcp @upstash/context7-mcp ...
```
```json
{ "command": "/путь/к/node", "args": ["/Users/<...>/.claude/mcp-bin/node_modules/.bin/playwright-mcp", "--browser", "chromium"] }
```

Проверять живым запросом, а не «должно работать»:
```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' \
  | node ~/.claude/mcp-bin/node_modules/.bin/<бинарь>
```
(На macOS нет команды `timeout` — тест, построенный на ней, даст ложное «не отвечает».)

### 2. Глобальный MCP — только тот, что нужен в ЛЮБОЙ папке

Глобальный сервер грузится в каждое окно. Разумный минимум — поиск по коду и документация.
Всё предметное (браузер, devtools проекта, мессенджеры, рекламные кабинеты, трекеры) живёт
в `projects["<путь>"].mcpServers` своей папки. Снятое с автозапуска не удалять — архивировать
(`~/.claude/mcp-parked.json`), чтобы вернуть одной строкой.

### 3. Тяжёлый гейт — через единую точку запуска с замком

Полный прогон (проверка типов + все тесты + сборка) стоит ~2.5 ГБ и минуты. Ничто не мешает
второй сессии запустить второй такой же поверх первого: замер — 9 одновременных `tsc`, своп
14.8 ГБ, машина стоит.

Замок single-flight имеет ДВА режима, и путать их дорого:

- **skip-if-busy** — для фоновых прогонов (post-commit): живой холдер уже покрывает HEAD,
  второй запуск избыточен.
- **queue-behind (`--wait`)** — для гейтов, чей вердикт связывающий (pre-push). Здесь пропуск
  = дыра: push уйдёт вообще без проверки. Второй запуск обязан дождаться и выполниться.

Проверять оба режима тестом, а не глазами: запустить медленный фиктивный гейт, поверх него
второй без флага (должен пропустить) и третий с флагом (должен дождаться и выполнить).

## Сторож

`~/.claude/scripts/mcp-reaper.sh` + LaunchAgent (раз в час). Критерий мусора — `PPID 1`:
родитель launchd означает, что сеанс-владелец мёртв. Живые сеансы и их дети не трогаются.
Классы: осиротевшие `uv`/MCP, брошенные `vitest`/`tsc` forks, осиротевшие `npm exec`,
зависшие проверки старше 30 мин (полный прогон ~6 мин, полчаса = зависло).

**Ловушка macOS:** штатный `awk` не принимает перенос строки после `(` в условии — условие
держать в одну строку, иначе `syntax error ... bailing out`, а скрипт всё равно вернёт 0
и запишет в лог успех.

## Что остаётся за системой

Число открытых окон — рычаг владельца, не движка. Даже с прямыми путями и проектным
скоупом десять окон дороже трёх. Это говорится прямо, а не чинится молча.
