# Модуль обязан импортироваться без последствий

Класс: `work-runs-at-import-time`. Закрыт 2026-08-15.

## Что было

Скрипт движка выполнял работу прямо на верхнем уровне файла. Пока его запускали
как команду, всё выглядело нормально. Но вызов import для соседнего модуля — это не чтение
файла, это его ИСПОЛНЕНИЕ, и любой импорт запускал чужой CLI целиком.

За одну сессию я налетел на это пять раз подряд: пытаешься импортировать модуль,
чтобы вызвать из него одну функцию, а он печатает свой отчёт, перезаписывает
индекс или молча виснет на чтении ввода. Каждый раз это выглядело случайностью.

Замер показал, что это уклад, а не случайность. Прогон импортировал каждый из
240 модулей в отдельном процессе, в копии репозитория:

| | до | после |
|---|---|---|
| печатают что-то при импорте | 86 | 0 |
| зависают (10 с и убиты) | 1 | 0 |
| падают при импорте | 0 | 0 |
| **файлов репозитория переписано** | **19** | **0** |

Девятнадцать переписанных — это индексы спек, карта покрытия ACs, реестр доступа
агентов, снимки памяти и файл в `global-setup/`. Никто их не менял: они
изменились оттого, что модули импортировали.

Отдельные находки того же корня:

- `scripts/dashboard/serve.mjs` при импорте **поднимал HTTP-сервер и занимал порт**;
- `scripts/skills-diff.mjs` при импорте **запускал подпроцесс** `gh auth token`;
- `scripts/tui-top.mjs` содержал обходной путь: он вырезал `--self-test` из
  `process.argv` перед импортами, потому что `collectors.mjs` запускал свою
  самопроверку при виде этого флага. Обход удалён — вместе с причиной.

## Правило

Верхний уровень модуля объявляет. Работает он только под сторожем:

```js
import { fileURLToPath } from 'node:url';
const isMain = process.argv[1] === fileURLToPath(import.meta.url);

if (isMain) {
  // всё, что делает работу: разбор аргументов, чтение, запись, вывод
}
```

Сторожем считается только сравнение `import.meta.url` с `process.argv[1]` (либо
сверка `argv[1]` с собственным именем файла — форма слабее, но свойство держит).
**`if (process.argv.includes('--self-test'))` сторожем НЕ является**: родительская
команда со своим флагом `--self-test` запустит чужую самопроверку.

Отдельно: `const __dirname = path.dirname(fileURLToPath(import.meta.url))` — это
путь, он всегда истинен. `if (__dirname)` не сторожит ничего. Кодмод один раз уже
написал 58 таких пустышек, и поймала это не самопроверка, а прогон поведения.

## Инструмент

```bash
node scripts/import-safety.mjs --all          # вся область движка
node scripts/import-safety.mjs <файлы…>       # выборочно
node scripts/import-safety.mjs <файл> --fix   # обернуть хвост в сторож
node scripts/import-safety.mjs --self-test    # 48 проверок
```

Гейт **статический и читающий**: он никогда не импортирует проверяемый файл,
потому что импорт — это ровно то действие, чью опасность он измеряет.

Точность откалибрована по факту, а не по ощущению: детектор прогнали против
эмпирического списка из 87 шумевших модулей, и он не пропустил ни одного. Всё,
что он пометил сверх этого списка, проверено глазами и оказалось настоящим
(хуки, читающие ввод, — в прогоне ввод был закрыт, поэтому они молчали).

## Область и её границы

Проверяются `scripts/`, `hooks/`, `lib/`, `global-setup/`, включая подпапки.

Исключены намеренно:

- папки с тестами: файл теста ПО ЗАМЫСЛУ выполняется при загрузке, это его
  способ регистрации;
- папки с образцами и предложениями: они нарочно неправильные.

Чего инструмент не видит, названо прямо:

- работу внутри объявления он ловит только для функций, объявленных В ЭТОМ ЖЕ
  файле (`const cfg = загрузить()`). Вызов импортированного помощника считается
  безобидным, иначе шумел бы каждый `path.join`;
- однострочная необязательная загрузка соседа через try с перехватом ошибки
  разрешена: это загрузка модуля, а не работа, и сам сосед обязан быть
  безопасным по этому же правилу.
  Если в том же блоке появляется любой другой вызов, исключение снимается.

## Где стоит

- `.githooks/pre-commit` — БЛОКИРУЕТ, но только по файлам этой правки
  (гейт соразмерен изменению);
- `.github/workflows/ci.yml` → `npm run gate:import-safety` — вся область;
- обе стороны блокируют одинаково: гейт не может быть мягким там, где работаешь,
  и жёстким там, где публикуешь.

## Чем доказано, что починка ничего не сломала

Поведение каждого из 240 модулей снято дважды — до правки и после — в двух
одинаково подготовленных копиях репозитория: как ведёт себя запуск командой и
что происходит при импорте.

- 226 из 239 команд ведут себя буква в букву как раньше;
- **ни одна не онемела** (главный риск: сторож, который выключил бы CLI);
- 12 расхождений объяснимы (счётчики модулей выросли на новый файл, живые
  данные о тратах, имя папки-песочницы в выводе);
- одно расхождение — улучшение: `selftest-reality.mjs` раньше падал по таймауту,
  а теперь отрабатывает, потому что перестал запускать чужую работу при импорте.

## Композиция

- Дополняет «Гейт проверяет ИЗМЕНЕНИЕ, а не весь репозиторий»: pre-commit смотрит
  только на файлы правки.
- Дополняет «Работающий гейт обязан быть ИЗВЕСТЕН реестру классов»: механизм
  несёт `@closes-class: work-runs-at-import-time`, регистрацию делает владелец.
- Родня классу `guard-bypassed-via-alternate-path`: обход в `tui-top.mjs` был
  ровно таким — вместо починки причины автор обошёл её у себя.
