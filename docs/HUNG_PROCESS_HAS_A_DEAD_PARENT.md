# Зависший процесс узнаётся по мёртвому родителю, а не по возрасту

**Класс:** `orphaned-process-outlives-its-session` · **Дата:** 2026-08-15 ·
**Происхождение:** projectx-app, автономный прогон

## Что случилось

В автономном прогоне владелец попросил проверять, не завис ли процесс.
Проверка нашла `scripts/run-fuzz.mjs`, который висел **5 часов 24 минуты**
при собственном потолке выполнения в 200 секунд — то есть завис вне своей же
модели времени.

Улика нашлась в дескрипторах: `lsof` показал, что вывод процесса указывает
в `->(none)` — сокет на той стороне закрыт. Родитель `ppid = 1`. Сессия,
которая его запустила, умерла ещё пять часов назад, а процесс продолжал ждать
события, которое уже не могло наступить: ноль процессора, сон, очередь
событий с одним никогда не срабатывающим ожиданием.

## Ловушка, из-за которой и написан документ

Рядом в списке висели **два процесса MCP по 18 часов**. Внешне — то же самое:
тот же `node`, тот же ноль процессора, та же вечность в выводе `ps`. Если
судить по возрасту и загрузке, их надо убивать вместе с фаззером.

Убивать их нельзя. Их родители — **работающие сессии Claude**. Убийство
сломало бы чужую живую работу посреди дела, причём незаметно: инструменты
просто перестали бы отвечать.

Единственное поле, которое отличает одно от другого, — родитель.

## Правило

Признак зависшего процесса — **не возраст и не нулевая загрузка**, а
**мёртвый родитель** плюс эти два признака вместе:

| Признак | Почему одного мало |
|---|---|
| сирота (`ppid = 1`) | демон бывает сиротой законно |
| без движения (процессор ≈ 0) | долгая сборка законно ждёт ввода-вывода |
| старше порога (30 мин) | процесс мог осиротеть секунду назад |

Процесс с живым родителем не трогается никогда, даже если висит сутки.
Его можно только назвать в отчёте.

## Инструмент

```
node ~/.claude/jidoka/scripts/process-health.mjs --root <проект>          # показать
node ~/.claude/jidoka/scripts/process-health.mjs --root <проект> --fix    # убрать сирот
node ~/.claude/jidoka/scripts/process-health.mjs --self-test              # 10 проверок
```

Решение вынесено в чистую функцию `приговор()`, поэтому правило «живого
родителя не трогаем» проверяется тестом, а не доверием: самопроверка гоняет
его на настоящих числах того случая — 324 минуты, `ppid 1`, ноль процессора
против 1080 минут с живым родителем.

`--fix` бьёт сначала `SIGTERM`, ждёт две секунды и только потом `SIGKILL`:
процессу дают закрыть файлы. В реальном случае фаззер на `SIGTERM` не
отреагировал (он спал в очереди событий) и потребовал `SIGKILL` — это
нормальный исход, а не сбой.

## Композируется с

- `stuck-detector.mjs` — та же беда на другом уровне: там зацикливается
  АГЕНТ (повтор действия, пинг-понг), здесь висит ПРОЦЕСС операционной
  системы. Разные оси, оба нужны.
- «Тяжёлую проверку делает координатор» — хвосты чаще всего остаются
  именно от параллельных прогонов тяжёлых проверок.
