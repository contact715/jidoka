# safe-commit.mjs небезопасен, когда рядом работает вторая сессия

Происхождение: projectx-app 2026-07-31. Агент правил 5 текстовых файлов, застейджил их
явно (`git add <5 files>`), запустил `safe-commit.mjs`. В той же папке параллельно работала
другая сессия с 66+ незакоммиченными файлами. `safe-commit.mjs` (строка 112: `git add -A`)
подмёл в коммит ВСЁ, включая 140-мегабайтный `.next-mocks/` webpack-кэш чужой сессии.
GitHub отклонил пуш по лимиту размера файла — это и спасло от тихой порчи истории под чужим
коммитом с неправильным сообщением. Откат сделан безопасно (`git reset --mixed HEAD~1`).

## Проблема

`safe-commit.mjs` вызывает `git add -A` безусловно, не считаясь с тем, что уже застейджено
вызывающим. Это разумно для одиночной сессии («закоммить всё, что я наработал»), но опасно,
когда рядом другая сессия держит в рабочем дереве большие незавершённые изменения — они
попадут в чужой коммит целиком, под чужим сообщением.

## Правило

Не использовать `safe-commit.mjs`, если `git status --short` показывает много файлов,
явно не относящихся к текущей задаче (другие компоненты, чужие scratch-файлы, посторонние
модули) — это признак параллельной сессии. В этом случае коммитить вручную:

1. `git add <явные пути>` — только то, что относится к задаче.
2. `git diff --cached --name-only` — сверить, что список РОВНО ожидаемый (плюс легитимные
   производные от pre-commit хуков, если они есть — но проверить их диф тоже).
3. `git commit -m "..."` напрямую.
4. `git push` вручную, с той же осторожностью — `safe-commit.mjs`'s rebase-on-conflict
   безопасность в этом сценарии недоступна, поэтому перед пушем `git fetch` + сверить, что
   origin не уехал.

## Нерешённое (не патчил безусловно — нужно решение владельца)

Сам скрипт стоит сделать безопаснее — например: если на входе уже есть staged-файлы,
коммитить только их, а не делать `add -A` поверх; или предупреждать/останавливаться, если
`git status --short` показывает много посторонних изменённых файлов вне явно переданных
путей. Это общая инфраструктура для всех проектов — не патчить молча, обсудить с владельцем
сначала.

Класс в мета-леджере: `unsafe-tool-in-shared-dirty-tree`.
