# Скрипт не глотает незнакомый флаг

Класс: `extra-argument-silently-swallowed`. Установлено 2026-09-16.

## Что было

Скрипты движка искали свои флаги подстрокой: `process.argv.includes('--fix')`,
`argv.indexOf('--repo')`. Всё, что скрипт не знал, он пропускал молча и делал свою работу.

- `safe-commit.mjs --help` запускал весь сценарий коммита и пуша. На чистом дереве с
  неотправленными коммитами он дошёл бы до `git push origin HEAD:main`.
- `claim-wave-id.mjs --brnach dev` (опечатка в `--branch`) отправлял резерв номера волны в
  ветку по умолчанию.
- `research-audit.mjs --bogus --self-test` выдавал зелёный и ничего не проверял.
- `jidoka.mjs relay --self-test` запускал самопроверку диспетчера, а не relay: диспетчер
  искал `--self-test` во всей строке, а не в своей части.

Замер того же дня (таблица: `docs/audits/CLI_STRICTNESS_2026-09-16.md`): в области
`scripts/`, `hooks/`, `global-setup/` было 269 CLI. Строгих среди них было 3: `safe-commit`,
`research-audit`, `create-tool`, причём последний на деле тоже не отказывал. Ещё 137
нестрогих скриптов пишут файлы, git, ходят в сеть, шлют сигналы или запускают агентов.

## Правило

Каждый CLI разбирает аргументы через `scripts/lib/cli.mjs`:

```js
import { runCli } from './lib/cli.mjs';

export const CLI = {
  name: 'task-queue',
  summary: 'Строго последовательная очередь задач.',
  selfTest: true,
  options: { repo: { type: 'string', value: 'путь', desc: 'где делать' } },
  commands: { next: {}, done: { positionals: { min: 1, max: 1, name: 'id' } } },
};

if (isMain) {
  const { command, values, positionals, selfTest } = runCli(CLI);
  ...
}
```

Что это даёт:

- незнакомый флаг, лишнее слово, флаг без значения, неверная команда или слово вне списка
  дают отказ до любой работы: в stderr причина, «Ничего не выполнено.» и справка, код 2;
- `--help` и `-h` печатают справку и выходят с кодом 0;
- `--self-test` существует только у скрипта, который объявил `selfTest: true`. Иначе скрипт
  без самопроверки разобрал бы этот флаг и молча пошёл бы работать;
- текст, начинающийся с дефиса (`- пункт`, `-5`), берётся как есть, как у `git commit -m`.
  Значение, похожее на флаг (`--repo --json`), считается ошибкой: забытое значение не должно
  тихо превратиться в следующий флаг;
- слово, которое пытается быть флагом, но флагом быть не может, — тоже отказ, а не позиционное
  слово: `--fiх` с кириллической «х», `—fix` после автозамены, `--fix ` с хвостовым пробелом,
  `--foo.bar`, `-х`. Такой текст передаётся после `--` или через `=`;
- число принимается только в десятичной записи: `' '`, `0x10`, `1e3` дают отказ;
- умолчания и списки значений флагов подкоманды действуют только в этой подкоманде;
- спецификация экспортирована под именем `CLI`, и все места вызова сверяются с ней
  автоматически;
- ошибка в самой спецификации — неизвестный тип, опечатка в любом поле (верхний уровень,
  флаг, позиционные слова, подкоманда), `badCallExit` не 1 и не 2 — бросает исключение, а не
  выдаётся за неверный вызов и не меняет правило молча.

### Хуки Claude Code: код отказа 1

Для хука код 2 значит «заблокировать». У `PreToolUse` блокируется вызов инструмента, у
`UserPromptSubmit` стирается сообщение человека, у `Stop` запрещается завершение. Если хук
ответит кодом 2 на опечатку в `~/.claude/settings.json`, сессия окажется заперта. Поэтому хук объявляет
`badCallExit: HOOK_BAD_CALL_EXIT` (это 1): Claude Code показывает такую ошибку, но ничего не
блокирует. Помощник хук загружает через `hooks/lib/load-cli.mjs` из собственного дерева:
сначала раскладка установки (`~/.claude/hooks` → `~/.claude/jidoka/scripts/lib`), потом
канон. Домашний каталог не используется. Найденный файл узнаётся по тексту до импорта:
импорт чужого одноимённого файла означал бы его запуск.

Сторож это требует, а не только советует. Хуком считается файл из `hooks/` (кроме `hooks/lib/`),
из `global-setup/hooks/`, строка состояния (`statusline-*.mjs`) и любой скрипт, который по имени
подключён в `global-setup/settings-hooks-fragment.json` (например `skill-selector.mjs --hook`).
Без `badCallExit: 1` такой файл — нарушение.

## Механизмы

| Что | Где | Когда |
|---|---|---|
| статический сторож | `scripts/cli-strictness.mjs` | pre-commit (файлы правки), CI (`npm run gate:cli-strictness`) |
| живой договор | `scripts/__tests__/cli-contract.test.mjs` | CI, engine unit tests |
| сверка мест вызова | `scripts/__tests__/cli-callsites.test.mjs`; `cli-strictness.mjs --callsites --home` | CI (репозиторий); на машине владельца вместе с `~/.claude` |
| живая проверка импорта | `cli-contract.test.mjs`, блок «импорт модулей ничего не делает» | CI |

**Сторож** читает текст и файлы не запускает: запуск с незнакомым флагом и есть та
опасность, которую он измеряет. Область — `scripts/`, `hooks/`, `lib/`, `global-setup/`. CLI
для него — модуль, где сравниваются `import.meta.url` и `process.argv` (в любой форме записи).
Строгим он считает только разбор через помощник: настоящий импорт `runCli` из `cli.mjs` или
загрузчик `load-cli.mjs`, плюс `export const CLI`. `util.parseArgs` в строгом режиме строг, но
спецификации для сверки мест вызова у него нет, поэтому он тоже нарушение. Слово `parseArgs` в
комментарии, упоминание `lib/cli.mjs` в строке и своя функция `runCli` строгостью не считаются —
это кейсы расхождения в его самопроверке. Побочные действия определяются построчно: git-запись, запуск агента,
удаление, сеть, сигналы, запись файлов. Строки-сообщения, регулярные выражения и
действия внутри самопроверки отдельно.

**Храповик** `docs/metrics/cli-strictness-baseline.json` хранит нестрогие CLI без побочных
действий с причиной, почему файл не переведён. Он только сжимается: починенный или
удалённый файл сторож требует убрать из списка, а число записей не может превысить потолок
`RATCHET_CEILING` в самом стороже. С 2026-09-16 потолок 0: все CLI строгие. Поднять его можно
только правкой сторожа, и это видно в диффе механизма, а не в тихо дописанном списке.
Скрипт с побочными действиями в храповике жить не может.

Коды сторожа: 0 — нарушений нет; 1 — нарушение, устаревший храповик или сломанный вызов;
2 — неверный вызов (несовместимые режимы, нет файла или папки); 3 — мерить было нечего
(пустая область при `--all`, ни одного места вызова).

**Живой договор** проверяет только то, что сторож признал строгим, и только в песочнице
`scripts/lib/cli-sandbox.mjs`. Песочница подменяет запись, переименование и удаление файлов
(в том числе через открытый дескриптор), запуск команд и `worker_threads`, сеть (`http`, `net`,
включая `net.Server#listen` и `Socket#connect`, `tls`, `dgram`, `dns`, `fetch`, `WebSocket`),
сигналы и `process.execve`, отчёт процесса и снимок кучи, а каждую попытку записывает. Сама
песочница при импорте ничего не делает: её включает предзагрузка `preloadUrl()`. У неё есть
свой красный тест: временный модуль пытается действовать всеми этими путями. Запуск идёт из пустой
временной папки с пустым HOME. Ожидается: `--help` → 0 и справка; незнакомый флаг → 2
(у хука 1), имя флага названо, ни одной попытки действия.

**Сверка мест вызова** (`scripts/lib/cli-callsites.mjs`, `scripts/lib/cli-replay.mjs`)
находит текстовые вызовы `node …scripts/x.mjs <аргументы>` в хуках git, CI, `package.json`,
shell-скриптах, строках JS и документации. Каждый такой вызов разбирается спецификацией
скрипта той же функцией, что и при запуске. Диспетчер сверяется по цепочке: хвост
`jidoka.mjs relay …` сверяется со спецификацией `jidoka-relay.mjs`. Хук, поставленный из
`global-setup/hooks/`, и строки состояния из `~/.claude` находят свою спецификацию в каноне.
Из установки (`node ~/.claude/jidoka/scripts/cli-strictness.mjs --callsites --home`, так её
советует звать `CLAUDE.md`) сверка тоже честная: файлы `global-setup/` ищутся там, куда их
кладёт установка (`~/.claude/`), а архив хуков продукта `local-hooks/` пропускается — его
`node scripts/x.mjs` зовёт скрипт продукта, а не движка.

Заполнители бывают двух видов. Заполнитель документации (`<файл>`, `{id}`) становится словом
`X`: он может стоять и на месте подкоманды (`<subcommand>`). Значение запуска (`$ARGUMENTS`,
`"$f"`) становится `$X`: если скрипт не принимает слов, такой вызов сломан, как было с командой
`/stats`, которая передавала `cc-stats.mjs $ARGUMENTS`. Вызовы из `package.json`, с многоточием
или с кавычкой, ушедшей за строку, считаются неполными.

Сломанным считается и вызов модуля без точки входа с аргументами (он их не читает), и вызов
скрипта движка, которого нет, если он записан в исполняемом тексте или инструкции. Строки внутри
*.mjs и папка `__tests__` для этой проверки — данные, а не вызовы. История (`docs/retros/`,
`audits`, `research`, брифы волн и т. п.) в отказ не идёт: это записи прошлого. Спецификации
модулей — живые: их проверки приёмки исполняет `ac-verify-map`.

**Живая проверка импорта** импортирует все модули области в песочнице. Она нашла то, что
статический `import-safety` пропустил: `current-wave-status.mjs` трижды звал `execSync`
при импорте и глотал ошибки, `dashboard/serve.mjs` создавал HTTP-сервер,
`test-reasoning-bank.mjs` создавал временную папку.

## Установка

`scripts/lib/` едет вместе со скриптами:

- `install-into.mjs`: `LIBS = ['lib/cli.mjs']` в каждом профиле;
- `install-global.sh`: копирует `scripts/lib/*.mjs`.

Проверка замкнутости импортов в `install-into --self-test` раньше видела только ./x.mjs и
была зелёной над установкой, где `./lib/cli.mjs` не доехал бы. Теперь она видит и подпапки.

## Чего механизмы не ловят

- Вызов в форме массива (`spawnSync(node, [SCRIPT, '--x'])`) сверка мест вызова не
  разбирает и не выдумывает.
- Вызовы из продуктов, у которых своя установленная копия движка (`.jidoka/scripts/`), сверка
  не собирает: `--home` смотрит только `~/.claude`. Три таких вызова в projectx-app сверены
  вручную. Копии скриптов в продуктах обновятся при следующей установке (`install-into` везёт
  и `scripts/lib/`). Отдельная копия одного файла (`projectx-app/scripts/claim-wave-id.mjs`)
  без `lib/cli.mjs` работать не будет — копировать нужно вместе с ним.
- Shell-скрипты (`*.sh`) этим правилом не покрыты. `mcp-reaper.sh` на `--help` шлёт SIGTERM;
  перевод shell-скриптов — отдельная задача.
- Песочница не видит прямых привязок (`process.binding`, `internalBinding`), родных модулей,
  WASI, inspector и записи через дескриптор, открытый до её загрузки.
- Побочные действия, которые скрипт получает через импортированную библиотеку, сторож
  по тексту не видит. Именно поэтому строгий разбор обязателен для ВСЕХ CLI, а не только
  для тех, у кого действия нашлись.
