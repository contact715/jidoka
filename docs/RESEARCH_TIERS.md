# Ресёрч пропорционален вопросу — два уровня, один набор инвариантов

Установлено 2026-08-18 (projectx-app). Владелец: «я хочу чтобы была более лёгкая версия,
более быстрая, когда я прошу просто сделай ресёрч… давай заложим какой то пропорциональный
процесс ресёрчинга качественного».

## Что было сломано

Правило «Сделай ресёрч = дип-ресёрч + дебаты + суд» (установлено 2026-07-29) имело ОДИН
режим и этот режим был тяжёлым. Отсюда два отказа, оба тихие:

1. **На маленьком вопросе тяжёлый прогон не запускался вообще.** Полчаса агентов ради
   одного факта из документации выглядят нелепо, поэтому вместо процесса включалось
   «почитал и рассказал» — ровно то, что правило запрещало. Правило без второй передачи
   не смягчается, оно обходится.
2. **Форма прогона придумывалась заново каждый раз.** Правило жило прозой в `CLAUDE.md`:
   ни скилла, который включается от слов владельца, ни прибора, который смотрит результат.
   Значит качество прогона равнялось тому, насколько агент в этот раз вспомнил правило
   целиком. Класс: `process-lives-only-in-prose`.

## Что теперь

**Скилл** `research` (канон `global-setup/skills/research/SKILL.md`, установлен в
`~/.claude/skills/research/`) включается на широком наборе формулировок и ПЕРВЫМ делом
проводит триаж по баллам: 0–2 → лёгкий уровень, 3+ → тяжёлый. Уровень называется
владельцу вслух. Тихое занижение — класс `research-depth-silently-downgraded`.

| | лёгкий («сделай ресёрч») | тяжёлый («дип-ресёрч») |
|---|---|---|
| линз разведки | 3, одна обязательно «наша сторона» | 5–7, пять из них обязательные |
| замер по фактам | один агент | по группам |
| состязательность | один скептик на опровержение | обвинение и защита ВСЛЕПУЮ |
| суд | выносит основная сессия | отдельная фаза |
| критик полноты | короткий, обязателен | обязателен, сверяет имена вход↔выход |
| ориентир | 4–6 агентов | 12–16 агентов |

Лёгкий уровень ПОВЫШАЕТСЯ посреди работы, если замер вскрыл архитектурный вопрос.
Повышение объявляется вслух.

## Пять инвариантов — держатся на ОБОИХ уровнях

Уровни отличаются объёмом, а не честностью.

1. У каждого внешнего утверждения есть источник и его СИЛА: `первоисточник` /
   `сторонний` / `вывод`. Без этого блог весит столько же, сколько документация вендора.
2. У каждого утверждения о НАШЕМ коде есть адрес `путь/файл.tsx:строка`.
3. Раздел «чего не проверил и почему» обязателен.
4. Результат — файл в проекте, а не только сообщение в чате.
5. Перед сдачей — `research-audit.mjs`.

## Прибор

```
node ~/.claude/jidoka/scripts/research-audit.mjs --doc <документ> --tier light|deep
node ~/.claude/jidoka/scripts/research-audit.mjs --self-test    # 32 проверки
```

Смотрит ВНУТРЬ документа и ловит семь классов: источник без метки силы, статус
«есть»/«частично» без адреса файла, отсутствие раздела непроверенного, заглушки
(TODO/TBD/допишу), и для тяжёлого уровня — отсутствие приговоров, первого шага, стоимости.

Две детали, ради которых прибор написан именно так:

- **Статус сверяется по ЯЧЕЙКЕ таблицы целиком, а не по вхождению подстроки.** Иначе
  «есть риск дублирования» читается как статус «есть» и требует адреса файла. Это тот
  же класс, что `guard-fires-on-mention-not-action`, только внутри разбора текста.
- **Путь без номера строки доказательством не считается.** Имя файла называет файл,
  имя файла с двоеточием и номером называет МЕСТО. Первое проверяется взглядом,
  второе — переходом.

Ось прибора отличается от `synthesis-coverage-audit.mjs`: тот сравнивает документ с
ИСТОЧНИКАМИ-файлами и ловит пропущенное, этот смотрит только внутрь документа и ловит
недоказанное. Когда источники это файлы (транскрипт, анкета, выгрузка) — гоняются оба.

## Семь усилений тяжёлого уровня

Замерены на прогоне 2026-08-18 (инбокс Mosco против respond.io), где каждая дыра
проявилась в живом виде:

1. **Сила источника различается.** Раньше блог и документация весили одинаково.
2. **Статус «есть» без адреса понижается автоматически.** Раньше замерщик мог
   ответить рассуждением.
3. **Дебаты вслепую названы явно.** Правило говорило «одновременно и независимо», но
   ничто этого не обеспечивало; стороны, видящие друг друга, начинают согласовывать.
4. **Критик полноты сверяет имена кандидатов на входе и в приговорах.** Кандидаты,
   тихо исчезнувшие между фазами, — типовая утечка тяжёлого прогона.
5. **Приговор несёт СТОИМОСТЬ.** Вердикт «берём» без ответа «делается ли это без
   правки чужого бэкенда и сколько занимает» — пожелание, а не решение.
6. **Результат обязан быть документом.** Раньше правило говорило «сохраняется в проект»
   без прибора, который это проверит.
7. **Потолок агентов объявляется ДО запуска,** и при нехватке режется охват, а не
   глубина; отрезанное называется вслух через `log()`. Молчаливая обрезка читается
   как полное покрытие.

## Композиция

- `RESEARCH_COVERAGE_SELF_AUDIT.md` — самоаудит покрытия источников (та же семья)
- `SYNTHESIS_COVERAGE_GATE.md` — сверка документа с файлами-источниками (другая ось)
- `NO_FABRICATED_SPECIFICS.md` — выведенный факт не факт
- `MULTI_REPO_CANONICAL_SOURCE_DECAY.md` — «такого нет» после проверки всех копий
- `HEAVY_CHECKS_BELONG_TO_THE_COORDINATOR.md` — почему тяжёлое не раздаётся каждому агенту

Классы: `research-depth-silently-downgraded`, `research-claim-without-evidence`,
`process-lives-only-in-prose`.
