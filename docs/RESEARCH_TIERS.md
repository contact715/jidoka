# Ресёрч пропорционален вопросу — два уровня, один набор инвариантов

Установлено 2026-08-18 (projectx-app). Владелец: «я хочу чтобы была более лёгкая версия,
более быстрая, когда я прошу просто сделай ресёрч… давай заложим какой то пропорциональный
процесс ресёрчинга качественного».

## Что было сломано

Правило «Сделай ресёрч = дип-ресёрч + дебаты + суд» (установлено 2026-07-29) имело ОДИН
режим и этот режим был тяжёлым. Отсюда два отказа, оба тихие:

1. **На маленьком вопросе тяжёлый прогон не запускался вообще.** Полчаса агентов ради
   одного факта из документации выглядят нелепо, поэтому вместо процесса включалось
   «почитал и рассказал» — ровно то, что правило запрещало. Правило без второй передачи
   не смягчается, оно обходится.
2. **Форма прогона придумывалась заново каждый раз.** Правило жило прозой в `CLAUDE.md`:
   ни скилла, который включается от слов владельца, ни прибора, который смотрит результат.
   Значит качество прогона равнялось тому, насколько агент в этот раз вспомнил правило
   целиком. Класс: `process-lives-only-in-prose`.

## Что теперь

**Скилл** `research` (канон `global-setup/skills/research/SKILL.md`, установлен в
`~/.claude/skills/research/`) включается на широком наборе формулировок и ПЕРВЫМ делом
проводит триаж по баллам: 0–2 → лёгкий уровень, 3+ → тяжёлый. Уровень называется
владельцу вслух. Тихое занижение — класс `research-depth-silently-downgraded`.

| | лёгкий («сделай ресёрч») | тяжёлый («дип-ресёрч») |
|---|---|---|
| линз разведки | 3, одна обязательно «наша сторона» | 5–7, пять из них обязательные |
| замер по фактам | один агент | по группам |
| состязательность | один скептик на опровержение | обвинение и защита ВСЛЕПУЮ |
| суд | выносит основная сессия | отдельная фаза |
| критик полноты | короткий, обязателен | обязателен, сверяет имена вход↔выход |
| ориентир | 4–6 агентов | 12–16 агентов |

Лёгкий уровень ПОВЫШАЕТСЯ посреди работы, если замер вскрыл архитектурный вопрос.
Повышение объявляется вслух.

## Пять инвариантов — держатся на ОБОИХ уровнях

Уровни отличаются объёмом, а не честностью.

1. У каждого внешнего утверждения есть источник и его СИЛА: `первоисточник` /
   `сторонний` / `вывод`. Без этого блог весит столько же, сколько документация вендора.
2. У каждого утверждения о НАШЕМ коде есть адрес `путь/файл.tsx:строка`.
3. Раздел «чего не проверил и почему» обязателен. Это заголовок, а не фраза в тексте;
   порядок слов любой («## Чего проверить не удалось и почему» тоже засчитывается).
4. Результат — файл в проекте, а не только сообщение в чате.
5. Перед сдачей — `research-audit.mjs`.

## Прибор

```
node ~/.claude/jidoka/scripts/research-audit.mjs --doc <документ> --tier light|deep
node ~/.claude/jidoka/scripts/research-audit.mjs --self-test    # 111 проверок
node ~/.claude/jidoka/scripts/research-audit.mjs --help
```

Смотрит ВНУТРЬ документа и ловит девять классов: источник без метки силы, ссылка без
схемы, статус «есть»/«частично» без адреса файла, отсутствие раздела непроверенного,
заглушки (TODO/TBD/допишу), пустота на обеих осях, и для тяжёлого уровня — отсутствие
приговоров, первого шага, стоимости.

Коды выхода: `0` чисто, `1` нарушения, `2` ошибка вызова (незнакомый флаг, флаг без
значения, лишнее слово; работа не начиналась), `3` проверять было нечего.

Две детали, ради которых прибор написан именно так:

- **Статус сверяется по ЯЧЕЙКЕ таблицы целиком, а не по вхождению подстроки.** Иначе
  «есть риск дублирования» читается как статус «есть» и требует адреса файла. Это тот
  же класс, что `guard-fires-on-mention-not-action`, только внутри разбора текста.
- **Путь без номера строки доказательством не считается.** Имя файла называет файл,
  имя файла с двоеточием и номером называет МЕСТО. Первое проверяется взглядом,
  второе — переходом.

## Зелёный, который ничего не проверил (2026-09-16)

Случай из projectx-app, документ «docs/03-research/2026-09-16-home-dashboard-vs-reference.md».
Внешние ссылки были записаны без схемы («help.getjobber.com/...»), статусов «есть» и
«частично» в таблицах не стояло. Прибор нашёл 0 источников и 0 строк замера, то есть
не проверил ничего, и напечатал «✓ дисциплина доказательств соблюдена» с кодом 0 на
уровне deep. Класс `green-check-that-checks-nothing`: тишина читается как успех.

Что изменилось:

- **Ссылка без схемы засчитывается источником и отдельно ловится** (`SOURCE-NO-SCHEME`).
  Считать её надо, иначе на ней молчит проверка метки силы. Ругаться на неё тоже надо:
  без `https://` она не кликается в разметке и не проверяется машиной
  (`scripts/verify-claims.mjs:50` берёт только ссылки со схемой). Одна ссылка, записанная
  по-разному (со схемой и без, с `/` на конце, в `**…**` или «…», с заглавными в хосте),
  это один источник (`sourceKey`). Ссылки со схемой и подписи markdown-ссылок
  `[a.com/x](https://a.com/x)` вырезаются до поиска голых, поэтому ни подпись, ни домен в
  параметрах (`?u=foo.com/bar`) вторым источником не становятся.
- **Хост засчитывается только с зоной из двух закрытых списков** (`GENERIC_TLDS`,
  `COUNTRY_TLDS`), расширения файлов исключены заранее. Так «Next.js/React» и
  `lib/api/client.ts:848` ссылками не считаются. Правило «любая двухбуквенная зона» и
  открытый список слов пробовались и ловили код: замер по 1590 документам нашёл
  «store.approve/decline», «payment.send/refund», «task.create/complete»,
  «company.name/address», ревью добавило «lead.id/deal.id», «fs.rm/unlink»,
  «messages.en/ru». Поэтому в списках нет глаголов, имён полей и коротких зон, совпадающих
  с частыми словами (`id`, `en`, `is`, `in`, `it`, `at`, `to`, `me`, `no`). Код в обратных
  кавычках не исключается: там 30 уникальных настоящих ссылок (44 вхождения) вида
  «github.com/Mosco-corp/back» (https://github.com/Mosco-corp/back).
  Цена выбора закреплена проверкой-расхождением («редкая зона вне списка»): ссылка без схемы
  на зоне вне списков («example.travel/x») не считается. Так сделано сознательно:
  пропущенный источник при нуле источников всё равно поднимет предупреждение, а ложный
  источник это предупреждение спрячет. После правки все 129 уникальных ссылок без схемы,
  которые прибор находит в тех 1590 документах, проверены глазами: это настоящие хосты.
- **Пустота на обеих осях не бывает зелёной** (`EMPTY-EVIDENCE`). Если источников 0 и
  строк замера 0, прибор ищет признаки того, что проверять было что: голый домен, таблицу
  со столбцом «Статус» без словарных статусов, слова о сравнении («конкурент»,
  «референс», «рынок») или о замере. Признаки есть, значит на лёгком уровне это
  предупреждение с кодом 3 и подсказкой, где смотреть. На тяжёлом уровне пустота это
  нарушение всегда: там замер и первоисточники обязательны. Внутренняя заметка без
  признаков получает код 0, но строка итога честно говорит, что проверены только раздел
  непроверенного и заглушки. Слово «соблюдена» печатается, только когда было что
  проверять.
- **Незнакомый флаг останавливает скрипт до любой работы.** Разбор идёт через
  `util.parseArgs` в строгом режиме: `--help` печатает справку, а `--bogus --self-test`
  больше не запускает самопроверку молча. Тот же дефект нашёлся в `safe-commit.mjs`,
  и там он опаснее. `--help` игнорировался, запускался весь сценарий, и при чистом
  дереве с неотправленными коммитами он доходил до `git push origin HEAD:main`. Там
  разбор тоже стал строгим, код 2 означает, что ничего не запускалось. Сообщение коммита
  берётся как есть, как у `git commit -m`: «- пункт» проходит, а значение в форме флага
  (`-m --no-push`) остаётся ошибкой, чтобы забытое сообщение не стало коммитом. Второе
  изменение поведения: `--wait 0` и `--wait abc` теперь ошибка, раньше молча было 120.

Прогон по корпусу 2026-09-16 (72 документа из «projectx-app/docs» и
«jidoka-framework/docs/research», по два уровня, 144 прогона): код выхода изменился в
29 прогонах. 10 из них дали ссылки без схемы (всего в корпусе 69 уникальных таких
ссылок, глазами проверены все). 19 дала пустота: 13 предупреждений на лёгком уровне и
6 нарушений на тяжёлом. Это документы, которые говорят о замере, рынке или конкурентах,
а прибору в них проверять нечего.

Граница, которая осталась и закреплена проверкой-расхождением («deep с источниками и без
строк замера»): на уровне deep при найденных источниках и нуле строк замера прибор молчит.
Столбец «Статус» есть и в таблицах итога («закрыто», «в работе»), поэтому отличить таблицу
замера от таблицы итога по заголовку нельзя. Эту дыру закрывает критик полноты на тяжёлом
прогоне, а не прибор.

Маркер `@closes-class: green-check-that-checks-nothing` у прибора сознательно не стоит.
Класс общий и уже закреплён за `oracle-divergence.mjs`. Второй маркер сказал бы реестру,
что класс закрыт везде, а здесь закрыт один его случай. Этот же случай уже был
2026-09-11: прибор дал зелёный ресёрчу, где источниками были база и файлы кода. Запись в
реестре ошибок была, починки не было, и 2026-09-16 класс повторился. Проверка пустоты
ловит обе формы, потому что смотрит на ноль проверенного, а не на вид ссылок.

Ось прибора отличается от `synthesis-coverage-audit.mjs`: тот сравнивает документ с
ИСТОЧНИКАМИ-файлами и ловит пропущенное, этот смотрит только внутрь документа и ловит
недоказанное. Когда источники это файлы (транскрипт, анкета, выгрузка) — гоняются оба.

## Раздел непроверенного это заголовок, в любом порядке слов (2026-09-18)

Прибор не принимал заголовок «## Чего проверить не удалось и почему» и печатал
`NO-UNCHECKED-SECTION` документу, где раздел был. Эту формулировку предписывает сам скилл
research: разведчик возвращает «чего по моей линзе проверить не удалось». Агенты в ответ
переписывали текст под прибор, хотя ошибался прибор. Класс
`measurement-tool-error-read-as-product-defect`.

Разбор показал вторую ошибку, в обратную сторону. Слова искались в ЛЮБОЙ строке, поэтому
фраза «цены мы не проверили» посреди абзаца засчитывалась за раздел, и документ без раздела
получал зелёный.

Что изменилось (`scripts/research-audit.mjs#findUncheckedSection`):

- раздел засчитывается только по заголовку: `# …` … `###### …` или строка, которая
  начинается с жирного `**…**`. У жирной строки смотрится только жирная часть, так что
  «- **Тарифы** не проверили» разделом не станет. Заголовки внутри блока кода не
  смотрятся;
- в заголовке принимаются оба порядка слов (`NOT_CHECKED_RE`): «не проверил», «не удалось
  проверить», «непроверенное», «нельзя проверить», «проверить не удалось», «проверено не
  было», «проверить нельзя», «not verified», «couldn't check», «unverified». Глаголы после
  «не» перечислены списком, иначе «Проверка не нужна» стала бы разделом. «Не» слева
  отделено от буквы, иначе «в зоне проверки» читалось бы как отрицание.

Замер на живых документах 2026-09-18: 122 уникальных документа с метками силы со всей
машины. У 105 вердикт не изменился. 5 стали зелёными: у них заголовок в обратном порядке,
все пять из корпуса Education. 12 стали красными, и все просмотрены глазами. Раньше их
пропускала случайная фраза в тексте. Три из них ресёрч без раздела
(`DEEP_RESEARCH_2026-06-08.md`, `06_суд_приговор.md`, `TOOLING_RESEARCH_2026-08-29.md`).
Восемь вообще не ресёрч, на них прибор не запускают: файл правил, отчёт графа, переписка,
SEO-журнал, спека и три контент-плана. Один документ ресёрча честно спорный:
`01_разбор-atticman.md` называет раздел «Чего в этом разборе нет и почему».

Граница закреплена в коде (`@divergence` у `findUncheckedSection`): заголовок без корня
«провер / check / verif» («Куда мы не смогли дотянуться», «Чего нет и почему») прибор не
узнаёт, setext-заголовки тоже. Лечится переименованием заголовка. Список синонимов без
общего корня начал бы ловить чужие заголовки.

## Семь усилений тяжёлого уровня

Замерены на прогоне 2026-08-18 (инбокс Mosco против respond.io), где каждая дыра
проявилась в живом виде:

1. **Сила источника различается.** Раньше блог и документация весили одинаково.
2. **Статус «есть» без адреса понижается автоматически.** Раньше замерщик мог
   ответить рассуждением.
3. **Дебаты вслепую названы явно.** Правило говорило «одновременно и независимо», но
   ничто этого не обеспечивало; стороны, видящие друг друга, начинают согласовывать.
4. **Критик полноты сверяет имена кандидатов на входе и в приговорах.** Кандидаты,
   тихо исчезнувшие между фазами, — типовая утечка тяжёлого прогона.
5. **Приговор несёт СТОИМОСТЬ.** Вердикт «берём» без ответа «делается ли это без
   правки чужого бэкенда и сколько занимает» — пожелание, а не решение.
6. **Результат обязан быть документом.** Раньше правило говорило «сохраняется в проект»
   без прибора, который это проверит.
7. **Потолок агентов объявляется ДО запуска,** и при нехватке режется охват, а не
   глубина; отрезанное называется вслух через `log()`. Молчаливая обрезка читается
   как полное покрытие.

## Композиция

- `RESEARCH_COVERAGE_SELF_AUDIT.md` — самоаудит покрытия источников (та же семья)
- `SYNTHESIS_COVERAGE_GATE.md` — сверка документа с файлами-источниками (другая ось)
- `NO_FABRICATED_SPECIFICS.md` — выведенный факт не факт
- `MULTI_REPO_CANONICAL_SOURCE_DECAY.md` — «такого нет» после проверки всех копий
- `HEAVY_CHECKS_BELONG_TO_THE_COORDINATOR.md` — почему тяжёлое не раздаётся каждому агенту

Классы: `research-depth-silently-downgraded`, `research-claim-without-evidence`,
`process-lives-only-in-prose`, `green-check-that-checks-nothing`.
