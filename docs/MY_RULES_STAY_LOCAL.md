# Моё правило в общем репозитории — обязанность для чужих людей

Владелец, projectx-app, 2026-08-24: «не заливать правила в гит, все правила
которые есть у тебя — локальные для работы с клодом».

## Что произошло

23 августа агент завёл правило линтера `no-raw-radius`, чтобы канон радиусов не
разъезжался, и сразу включил его как `error` в `eslint.config.mjs`. Правило
работало и было корректным. Проблема в другом: конфигурация репозитория
действует на КАЖДОГО, кто в нём работает. Коллеги получили блокировку коммитов
по договорённости, которой с ними никто не заключал, и пожаловались владельцу.

Ошибка не в правиле, а в его МЕСТЕ.

## Правило

Механизм, придуманный агентом для своей работы — правило линтера, храповик,
сторож, проверка канона — не кладётся в общие файлы репозитория:

    eslint.config.mjs, eslint-rules/, .husky/, .github/workflows,
    scripts в package.json, конфиги тестов

Место таких правил — `~/.claude/` (например `~/.claude/rules/local-lint/`).
Запускает их агент сам, по своей работе.

## Три различения

**Починка ≠ правило.** Исправить сломанный общий гейт — упор в память, таймаут,
ложный «успех» при обрыве — можно и нужно: это снимает препятствие для всех.
В том же инциденте агент поднял потолок памяти проверки типов, из-за которого
гейт был непроходим у всех; откат этой правки вернул бы поломку. Такое остаётся.

**Инструмент ≠ правило.** Кодмод, который никто не вызывает из хука или CI,
принуждает ноль людей. Может жить в репозитории: пользуется тот, кому надо.

**Канон для всех — решение владельца.** Если кажется, что договорённость стоит
закрепить механически, это разговор с командой, а не коммит агента.

## Как проверить себя перед коммитом

Вопрос один: **если это вольётся, у кого-то чужого перестанет проходить
коммит?** Если да — правило идёт в `~/.claude`, а не в репозиторий.

Класс: `my-rule-imposed-on-the-shared-repo`.
