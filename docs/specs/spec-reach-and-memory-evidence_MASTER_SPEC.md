# spec-reach-and-memory-evidence — Master Spec

## 1. Goal (business terms)

Две формы одного и того же изъяна: механизм существует, но в нужный момент до него не
дотягиваются.

Первая. Контекст спеки был доступен только по запросу: цепочку предков получал тот, кто знал,
что надо спросить, и знал имя фичи. В момент, когда это важнее всего, то есть при правке файла,
никто не говорил «этот файл регулируется вот этой спекой». Спеку читали, когда вспоминали, и
пропускали, когда правка выглядела мелкой, а это ровно тот случай, когда спеки нарушают.

Вторая. Единственным доказательством работы поиска по памяти был его собственный самотест: код,
писавший ранжирование, писал и ожидание к нему. Это не доказательство, а согласие с самим собой.

## 2. Mechanism

### 2.1 Индекс «путь → спека» и вставка в момент правки

`scripts/spec-path-index.mjs` строит соответствие кода и спек ПО ФАКТУ, а не по объявлению. Ни
одна спека в репозитории не имеет поля путей, и вводить его значило бы дописать 67 файлов ради
договорённости, которую никто не соблюдает. Но спеки называют код, который регулируют,
многократно: частота упоминаний и есть свидетельство. Одиночное упоминание правом на файл не
считается, это шум.

`hooks/spec-push.mjs` стоит на PostToolUse и после правки файла добавляет одну строку контекста
с именем регулирующей спеки. Он информирует и никогда не блокирует: хук, мешающий редактировать,
обменяли бы на тишину за неделю.

Обратная ось того же индекса отвечает на вопрос, который демон дрейфа не задавал никогда: есть
ли здесь код, которого никто не просил. Сигнал сужен до недавнего кода без спеки, потому что
старый код без спеки это история движка, а объявить непрошеными 190 файлов значило бы приучить
всех игнорировать детектор.

### 2.2 Внешнее свидетельство для памяти

`scripts/memory-eval.mjs` прогоняет поиск по памяти на золотых случаях, разложенных по пяти
способностям: извлечение, рассуждение через несколько сессий, время, обновление знания и
воздержание. Прогон детерминированный, без модели и без сети.

Воздержание это тот случай, который ранжирующий поиск не проходит случайно: вернуть что-нибудь
это ровно то, ради чего он написан. На вопрос, ответа на который в корпусе нет, система обязана
не отвечать.

## 3. Acceptance criteria (each maps to an executable self-test)

- **AC-1.1** Путь к скрипту, хуку и githook-файлу распознаётся в тексте спеки.
  → `scripts/spec-path-index.mjs --self-test`
- **AC-1.2** Спека с бОльшим числом упоминаний считается регулирующей; одиночное упоминание
  права на файл не даёт. → тот же самотест
- **AC-1.3** Обратная ось не считает непрошеным файл, у которого спека есть. → тот же самотест
- **AC-1.4** Свежий файл без спеки помечается отдельно от старого: окно настраивается.
  → тот же самотест
- **AC-2.1** Файл под спекой даёт строку вставки с её именем.
  → `hooks/spec-push.mjs --self-test`
- **AC-2.2** Файл вне известных корней и файл вне индекса не дают ничего. → тот же самотест
- **AC-2.3** Каталог, совпадающий по префиксу, но другой, не считается своим. → тот же самотест
- **AC-3.1** Верное первое попадание засчитывается, неверное нет, и в отчёте видно ожидание.
  → `scripts/memory-eval.mjs --self-test`
- **AC-3.2** Ответ на вопрос, которого нет в корпусе, считается ПРОВАЛОМ воздержания.
  → тот же самотест
- **AC-3.3** Промахи разложены по способностям, а не сведены в одно число. → тот же самотест
- **AC-3.4** Случай без проверяемого ожидания не может пройти молча. → тот же самотест

## 4. Wiring (not a ghost)

- `hooks/spec-push.mjs` — PostToolUse на Write, Edit и MultiEdit, в настройках Claude Code.
- Индекс: `docs/audits/spec-path-index.json`, пересобирается `scripts/spec-path-index.mjs --build`.
- `scripts/memory-eval.mjs` подключён в общий детерминированный набор `scripts/eval-suite.mjs`
  через `docs/evals/_cases.jsonl`, поэтому золотые случаи не остаются мёртвым файлом.
- Случаи: `docs/evals/memory-retrieve/golden-cases.jsonl`.


### Управление и настройка

- Пересобрать индекс: `spec-path-index.mjs --build`; спросить про файл:
  `--lookup <путь>`; обратная ось: `--reverse`, окно свежести `--days N`.
- Проверить память: `memory-eval.mjs`; сравнить каналы поиска: `--embed`; свой набор
  случаев: `--file <путь>`.

## 5. Out of scope

- Блокировка правки файла без спеки. Обратная ось сегодня отчёт, а не приговор: условие суда
  (наличие идентификаторов требований у кода) выполнено частично, 46 файлов из 247.
- Пробуждение векторного слоя памяти по умолчанию. Замерено и отклонено: только лексика даёт
  8 из 8 на золотом наборе, лексика с вектором 4 из 8. Решение перепроверяется командой
  `scripts/memory-eval.mjs --embed`.
