# Документ-синтез не сдаётся без сверки с источниками

**Класс в мета-леджере:** `synthesis-shipped-without-coverage-audit`
**Происхождение:** Rejuvenation Nation, 3 августа 2026

---

## Что произошло

Владелец четыре раза подряд в одной сессии спросил «ты точно всё учёл?». Каждый раз
находились пропуски:

| Заход | Что нашлось |
|---|---|
| 1 | Первая версия ТЗ сдана без сверки вообще |
| 2 | 15 пропущенных блоков: магазин ухода, рассрочка клиентам, реферальная программа, скидка новому клиенту, личный кабинет, подарочные сертификаты, интеграции Boulevard (Reserve with Google, Instagram Book Now, Widewail), выбор специалиста, требование полноты каталога по образцу конкурента |
| 3 | Ещё: мониторинг доступности сайта, посадочные страницы под акции, атмосфера локаций, языки обслуживания |
| 4 | Ещё: Yelp (4 упоминания в источниках, ноль в документе), способы оплаты, цифры неявок |

Слова владельца: «если бы я не спросил, ты бы всё проебал, и клиент бы потом вопросы
задавал».

---

## Корневая причина

Правило про аудит покрытия уже существовало с 28 июля. Оно не сработало по двум причинам.

**Причина 1: привязка к слову, а не к артефакту.** Правило начиналось со слов «Ресёрч не
сдаётся без собственного аудита покрытия». Написание ТЗ агент не классифицирует как
ресёрч: внутренняя формулировка звучит как «я оформляю то, что уже знаю». Категория не
совпадает, правило молчит.

**Причина 2: правило без форсирующей функции.** Текст в CLAUDE.md ничего не блокирует.
Для кода есть proof-of-work-gate, для UI есть browser-verify-gate, для исходящих сообщений
есть outbound-claims-gate. Для документов-синтезов не было ничего.

## Решение

### Инструмент: `scripts/synthesis-coverage-audit.mjs`

Механическая сверка документа с источниками.

```bash
node scripts/synthesis-coverage-audit.mjs \
  --doc "ТЗ-проект.md" \
  --sources "./sources/"        # папка или список файлов через запятую
```

Извлекает из источников:

- денежные суммы и проценты
- латинские названия продуктов и брендов
- цитаты в кавычках (прямая речь клиента)
- кириллические имена собственные

Проверяет каждую сущность на вхождение в документ, с учётом словоформ (сравнение по корню).
Выводит непокрытое, отсортированное по частоте упоминания в источниках: чем чаще говорили,
тем важнее пропуск.

Флаги: `--json` для машинного разбора, `--limit N` для длины вывода, `--self-test`
для 13 самопроверок.

**Это сеть, а не замена чтению.** Инструмент ловит крупные дыры. Смысловые пропуски
(например, «клиент сказал X, значит на сайте нужно Y») он не поймает, их ловит только
внимательное чтение источника.

### Гейт: `hooks/synthesis-coverage-gate.mjs`

Stop-хук. Логика:

```
если в сессии создан или изменён документ-синтез
и после этого не запускался synthesis-coverage-audit
→ заблокировать остановку один раз
```

Документ-синтез опознаётся по имени файла: ТЗ, смета, предложение, proposal, итоги, бриф,
аудит, анализ, spec, требования, план работ. Расширения: md, html, txt, doc, pdf.

Намеренно НЕ считаются синтезом: README, CHANGELOG, LICENSE, код, package.json. Точность
важнее полноты, ложное срабатывание раздражает и обесценивает гейт.

Контракт безопасности, тот же что у остальных гейтов:

- fail-open: любая ошибка или отсутствие транскрипта → пропускаем
- блокировка не более одного раза за сессию (файл-маркер в tmp)
- уважает `stop_hook_active`, не зацикливается
- 17 самопроверок

Регистрация в `~/.claude/settings.json` → `hooks.Stop`.

## Как это применять в работе

1. Перед сдачей любого документа-синтеза собрать источники в одну папку
2. Запустить сверку
3. Пройти по списку непокрытого глазами: пропуск или шум
4. Закрыть пропуски
5. В отчёте владельцу дать раздел «что проверено и чего проверить нельзя»

Пятый пункт обязателен. Непроверяемое называется явно, а не умалчивается.

## Композиция с другими правилами

- **No done without proof** — доказательство работы. Здесь доказывается ПОЛНОТА охвата
- **A specific you inferred is not a fact** — доказательство фактов внутри документа
- **Ресёрч не сдаётся без собственного аудита покрытия** — предшественник этого правила,
  остаётся в силе для формальных ресёрчей

## Дополнение от 4 августа 2026: смысловая сверка

Механическая сверка ловит пропавшие **сущности**: слово было в источнике, в документе его нет.
Она не ловит пропавшие **следствия**: клиент сказал X, из этого следует требование Y, и Y
в документе отсутствует. Слова при этом на месте.

Реальный пример из того же проекта. Владелец сказал: «первый экран должен продавать вход,
а не средний чек». В ТЗ попала фраза про первый экран, но с обратным смыслом: «дорогие
процедуры, ради которых строится первый экран». Механическая проверка это пропустила,
потому что все слова присутствовали. Поймал субагент, читавший источник с рамкой «деньги».

Поэтому гейт теперь засчитывает сверку двух видов:

| Вид | Чем выполняется | Что ловит |
|---|---|---|
| Механическая | `synthesis-coverage-audit.mjs` | пропавшие сущности: имена, суммы, названия, цитаты |
| Смысловая | субагент по навыку `synthesis-review` | пропавшие следствия и перевёрнутые смыслы |

Достаточно одной из двух: требовать обе на каждом коротком документе значит сделать гейт
раздражающим, а раздражающий гейт начинают обходить. На длинных документах и на всём,
что уходит клиенту, стоит делать обе.

Навык `skills/synthesis-review/SKILL.md` запускает несколько субагентов с разными рамками
(деньги, техника, риски, обещания клиенту), каждый читает источники целиком и возвращает
только то, чего в документе нет или что искажено.
