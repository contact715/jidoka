# Предложение в реестр классов: кириллические регулярки → `cyrillic-boundary`

Заведено 2026-10-10. Запись в `scripts/meta-remedies.mjs` делает ЧЕЛОВЕК: агент, который
может зарегистрировать себе гейт, может объявить себя безопасным. Всё ниже уже проверено на
копиях реестра; применение одной командой:

```
node ~/jidoka-framework/docs/proposals/apply-cyrillic-word-class.mjs
```

## Что это меняет

**1. Регистрирует два класса на один механизм `scripts/cyrillic-boundary.mjs`.**

- `ascii-word-boundary-blind-in-cyrillic` — `\b` вплотную к русской букве не срабатывает
  никогда. Четыре случая в августе, сторож стоит с 2026-08-26, но в реестре его не было,
  поэтому стартовая сводка считала класс живым риском без гейта.
- `ascii-word-class-blind-in-cyrillic` — новый, 2026-10-10. `\w` в JavaScript это только
  латиница, флаг `u` этого не меняет. Случай: research-audit не засчитывал адрес
  `CORP_структура_компании.md:15`, пять честных строк замера краснели. Опись дерева в тот
  день: 1691 регулярка, 307 с `\w` или `\b`; 10 русских правил не срабатывали ни разу,
  разборщики кода не видели русских имён функций (в движке их 197).

**2. Чинит пять регулярок в самом реестре.** Без этого pre-commit заблокировал бы коммит
регистрации: он теперь проверяет каждый изменённый `.mjs`, а реестр тоже `.mjs`.

| Строка | Что было | Что станет |
|---|---|---|
| `risk` около строки 231 | `жёстк\w* гейт` — фраза «жёсткий гейт» не находилась | `жёстк\p{L}* гейт`, флаг `u` |
| `clears` около строки 264 | `общ\w+ (класс…)` — «общий класс» не находился никогда | `общ\p{L}+ (класс…)`, флаг `u` |
| `clears` около строки 72 | английский словарь с `\.test\.` | без изменений, метка `@ascii-ok` с причиной |
| `risk` около строки 116 | английские глаголы и латинские имена файлов | без изменений, метка `@ascii-ok` |
| `risk` около строки 168 | английская похвала, `all \w+ passed` | без изменений, метка `@ascii-ok` |

Проверено до применения: на копиях обеих версий реестра (канон и `~/.claude/jidoka`) обе
записи встают, повторный запуск ничего не меняет, реестр разбирается, `cyrillic-boundary`
по нему зелёный, premortem ловит «поставим жёсткий гейт» и снимается «вынесем в общий класс».

## Чего это НЕ закрывает

`measurement-tool-error-read-as-product-defect` (6 записей) этим гейтом не закрыт. Только
одна из шести — регулярка с `\w` (2026-10-10). Остальные пять — другой механизм отказа:
не тот селектор, невидимый элемент, синтетические события вместо жеста. Записывать этот
класс в семейство `cyrillic-boundary` значило бы объявить гейт шире, чем он есть.
