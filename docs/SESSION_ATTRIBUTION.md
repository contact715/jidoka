# По подписи автора сессии неразличимы

Замер 2026-08-28. Все сессии на машине коммитят под одной подписью:

```
contact715 <contact@castells.media>
```

Значит вопрос «чей это коммит» из git не выводится вообще. Не приблизительно, не с
трудом — никак. И параллельных сессий сегодня бывает три-четыре.

## Как это выстрелило

Соседняя сессия (`projectx-app-d5`) увидела на main репозитория mosco-next коммит `b1784b202` с
красными тестами, который блокировал её пуши целый час. Она определила автора по подписи,
получила `contact715` и написала мне: «твой коммит, допуши компонент или откати тесты».

Коммит был не мой. Я в той сессии `billing-tool` не касался вовсе. Но доказать это из git
я тоже не мог — по подписи мы неразличимы в обе стороны.

Настоящая картина нашлась только обходом истории по тикету:

```
42509fbd4  14:18  fix(invoices): MOS-198 экран читает СЕРВЕР      → ветка «работа», НЕ на main
b1784b202  15:21  test(invoices): MOS-198 тесты к нему            → на main
```

Один тикет, две сессии, разошлись по времени. Тесты уехали, компонент остался.

## Цена

Час заблокированного `main` у соседа. Ошибочная просьба откатить чужую доказанную работу.
Полчаса разбора у меня. И худшее: сессия, которая это сделала, к моменту разбора уже
УМЕРЛА, оставив рабочую копию с 27 незакоммиченными файлами и 549 добавленными строками
без хозяина. Спросить было не у кого.

## Что предлагается

Строка-трейлер в сообщении коммита, которую ставит сама сессия:

```
Session: jidoka-88 [737e69]
```

Имя сессии у нас уже есть — его печатает `ListAgents`, по нему сессии шлют друг другу
сообщения. Трейлер не меняет автора коммита и не ломает подпись, он лишь добавляет строку,
по которой видно, кто именно работал.

Тогда сегодняшний разбор занял бы одну команду вместо получаса:

```
git log -1 --format='%(trailers:key=Session)' b1784b202
```

## Почему механизм НЕ поставлен этим же коммитом

Ставится он `prepare-commit-msg`-хуком, а хук включается через `core.hooksPath`, и он
ОБЩИЙ для всего репозитория, включая рабочие копии коллег (измерено 2026-08-24, см.
`hooks-reachability`). Глобальная установка задела бы каждый репозиторий на машине,
включая чужие боевые.

Это ровно тот случай, который закрывает правило «мои механизмы не кладутся в общий
репозиторий»: механизм, придуманный мной для своей работы, не включается молча тем, кто
о нём не договаривался. Решение о месте установки — за владельцем.

Промежуточный шаг, который ничего никому не навязывает: ставить трейлер РУКАМИ в своих
коммитах. Он бесплатен и уже полезен: одна сессия с трейлером отличима от всех прочих.

## Личность у сессии ЕСТЬ — её нет только в git

Замер 2026-08-29, важная поправка к разделу выше. Сессия различима на уровне связи:
её адрес это `/tmp/cc-socks/<pid>.sock`, и число в имени — настоящий номер процесса.

```
ps -p 81868 -o pid,ppid,lstart,command
81868  81866  Fri Aug 28 15:00:05 2026  .../claude-code/2.1.246/claude...
```

Значит утверждение «сессии неразличимы» верно ТОЛЬКО про git. В переписке они
различимы точно, и это проверяется одной командой.

Проверка пригодилась сразу. Соседняя сессия сначала трижды назвала коммиты MD-567/568/569
своими, потом сказала, что не называла их ни разу, и предположила, что мне писали две
разные сессии, склеившиеся в один адрес. Проверка процесса это опровергла: номер один,
процесс живёт непрерывно с 28 августа 15:00:05, все сообщения пришли от него.

Вывод при этом НЕ обвинительный. Самое вероятное объяснение — у соседа сжался контекст, и
он честно не помнит своих ранних слов. Именно поэтому запись и нужна: память сессии
теряется, а факт о процессе остаётся проверяемым.

Практическое следствие для протокола: **не спорить о памяти, а сверять процесс**. И
трейлер в коммите стоит нести не только имя сессии, но и её номер процесса — тогда
принадлежность работы проверяется тем же способом, что и авторство сообщения.

## Родство

- «Параллельные сессии — коммитить по очереди, не наперегонки» — там про гонку записи,
  здесь про невозможность узнать, кто записал;
- `uncommitted-work-wiped-by-parallel-session` (2026-08-28) — тот же корень: сессии не
  видят друг друга, поэтому вредят друг другу молча;
- «Мои правила не кладутся в репозиторий» — объясняет, почему хук здесь не поставлен.
